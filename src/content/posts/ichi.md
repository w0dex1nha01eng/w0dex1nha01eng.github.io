本项目旨在提高若只的动手能力

项目本身就很简易：让一个差速小车在带障地图里从起点开到终点，然后用两种方式学同一个A*的专家路径：一种是直接回归动作序列，另一种是用扩散模型生成动作序列
现在项目收尾了，结果我确实没想到：在这个任务上扩散并没有赢，两个方法成功率基本一样，但扩散慢了一百倍。我一开始就想做扩散，BC 只是对照组,结果有点奇异搞笑。过程倒是留下了不少东西，记一下。


模仿学习得先有专家数据，这块我用的是是 A\* 加纯跟踪——先规划一条网格路（就是四邻域），再沿着路开。这部分前后返工三次，主要是当时专家数据也不是很理想。第一次是我看 A\* 出来的路全是锯齿，觉得轨迹太脏，就写了个可视性检查，做的LOS把能连成直线的路点连起来，结果专家成功率从 80% 掉到 38.5%。第一反应当然是"净距检查写错了"，还专门写了个密集采样的测试去验证，结果检查是对的。后面又去扫净距余量和前视距离，扫了七八组，成功率就停在了 38%。到这一步其实已经说明我猜的不对。最后把失败轨迹一条条渲染出来看才发现：路点稀疏之后，纯跟踪会去瞄七八米外那个远路点，它对着远点的收敛轨迹是半径五米的大圆弧，机器人就一边慢慢转一边往前蹭，蹭到障碍上。修法也简单，不瞄路点了，在路径上插值出一个永远位于正前方 0.5 米的点。换完立刻回到 96% 以上（后来我为了做法又手贱把前视距离放大到 1 米、2 米，又掉到 86%、59%，证明就是0.5就可以）。

在做模仿学习的时候那边我先撞上的是另一件事。一开始数据只有 64 条轨迹，闭环成功率 42%，我加 dropout、加早停、加"训练完回滚到最佳 checkpoint"，验证 loss 从 0.105 磨到 0.101。后面还是扩数据：64 条扩到 300 条，loss 掉到 0.0657，闭环从 42% 涨到 63%，当时其他什么都没改这算是进步最大的一次改动了（应该）。然后在后面让ai帮忙总结项目的时候又发现一个点，上面所有数字都是在固定起点 (1,1)、固定终点 (9,7) 的设定里跑出来的，我另开了 200 张随机起终点的地图去测同一份模型，成功率 37.5%，122 张直接撞上去，就换了个起点终点而已。原来前面全是在温室里刷分。把起终点随机化塞进训练数据之后，同一批图复测 66.5%，接着发现初始朝向也一直是零，又是一个温室，也一起改了。

扩散这部分我之前没学过，论文和其复现代码也没彻底看懂，框架是我写 TODO 让 AI 帮我补的，DDPM 原文看到现在也没完全读懂，很多地方是靠查资料拼出来的。第一次跑闭环的结果我印象很深：0%，99% 的 episode 超时，机器人在原地打转。我最开始先怀疑采样代码写错了，公式对了一遍没问题；又怀疑训练崩了，loss 曲线正常。最后让ai帮忙加了个逐帧打印中间状态的部分，才发现问题在最后一步——cosine 调度终点的信噪比是 0，最后一步的公式里带着一个 1/sqrt(α)=31.6 的放大因子，去噪器那点误差被放大三十多倍，样本直接被推出训练分布然后雪崩。我用的修法比较草率，是跳过最后一步直接采样，没重新训练，成功率从 0% 变成 71%。这个修法说实话有点丑，但当时只想让它先跑起来。

改去噪器的时候我又遇到一个更反直觉的事。第一版我感觉是不是MLP到上限了，加了卷积和全局残差，正常来说网络在高噪声段的最优解本来就是照抄输入，残差等于给了一条捷径，改完高噪声段的误差从 0.12 掉到 0.008，十几倍。然后闭环跑出来 70.5%，比改之前还降了零点五。误差好了十五倍分数不动，我当时确实有点懵。后面让ai帮我再跑一遍看问题，继续拆才发现决定动作内容的是中间那段（t=10~30），而我的改动对那段基本没帮助；在deepseek的提议下换成 1D U-Net 之后中段误差从 0.15 掉到 0.076，闭环一口气涨到 82.5%。那次之后我就不迷信"网络做大"了，也不是扩散不行，至少我没有彻底掌握。

后面我又做了 DAgger，起因是分析失败案例时发现一个特别干净的现象：在所有训练数据里，正前方半米内有障碍的状态出现了 0 次。专家的习惯是提前一米就转，所以模型一旦因为误差累积漂到贴墙直行的位置，它就不避障了，应该就是出现了分布漂移。于是我让AI加上了每一步请专家从当前位置重新规划打上标签，把这些状态连同标签一起塞进数据集，撞了的轨迹也留着。后面我又给雷达最小距离小于半米的样本加了五倍权重（这类样本不到 2%，不乘权等于没加）。

```
lidar_minimum = observations[..., 6:].amin(dim=(1, 2))
return torch.where(lidar_minimum < threshold, weight, 1.0)
```

但是效果不明显：动作层面虽然有改善，该急转却不转的比例从 8.2% 降到 3.8%，扩散那边从 7.3% 降到 5.7%，但测试集总分纹丝不动，还是 84.5% 到 85%。跑了两轮、两个模型都是这个结果，说明剩下的问题不在这儿。

最后我把 200 张测试图按结果分组（这部分全权ai操作），用专家自己的最小净距去看难度：三个模型全失败的 9 张图，专家净距中位数只有 0.30 米，机器人半径是 0.25 米，等于专家也是贴着五厘米的余量钻过去的；而全部成功的 146 张图是 0.84 米，专家自己在那批图上的成功率也只有 96%。所以剩下那十几个点是被示范本身的精度封顶的，不是网络不够大——这点我加宽网络验证过，没用。

后面本来还做了份多模态的数据（加了个偏置），让专家在不同地图上分别从障碍上方或下方绕，用两条路线的动作取平均来模拟回归模型，成功率 67%，单走一条各自 94%~97%。

```
if lateral_bias >= 0:
    return 1.0 + lateral_bias * (y / height)      # 想靠下
return 1.0 + (-lateral_bias) * (1 - y / height)   # 想靠上
```

那是唯一一个扩散的采样能力应该显出优势的地方，数据我生成好了但没跑完（答案有点明显，也懒得继续了），扩散跑的太慢了，已经到了一次两三个小时了拖不动了。

最后的成绩就是四个模型挤在 84.5% 到 85.5%，扩散比 BC 慢一百倍。在这个单专家、单意图的导航任务上，扩散没赢。不过项目算是完整的，代码和配置都传 GitHub 了，项目里面要是用了加了偏置的专家数据说不定扩散会表现更好。
