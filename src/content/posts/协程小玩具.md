最近看到一篇博客 [莱莱博士-深入理解异步IO](https://microcai.org/2024/12/13/in-deepth-async.html) ，用一种"站在古代计算机视角看异步 IO"的讲法重新解读了这个问题。刚好我最近在看 C++20 里协程那部分，处于一知半解、什么也讲不出来的状态，但那篇博客里确实有几个点让我很受启发，比如那句"内核调度的多任务是线程，用户态调度的多任务就是协程"。这纠正了我之前对协程的误解——在那之前，我一直把协程当成"生成序列"的那种东西。于是我决定不依赖现成库，用裸 socket 和 poll() 写一个最简单的 TCP echo（其实对我不简单）。

一开始确实不知道从哪写起，就在网上找案例，几乎是照抄了一个 `DetachedTask` 类：不返回结果，创建之后还要手动调用 `start_detached()` 启动。抄来的东西确实有用，等第一个能靠 `co_await` 挂起的协程跑起来之后，好多概念突然就通了：协程只是把"接下来要干什么"保存在协程帧里，需要的时候再 `resume`。

接着就是事件循环。我用 `poll()` 写了个循环，维护一张表，记录"哪个 fd 就绪时该恢复哪个协程句柄"。这部分最难受（还是太菜）：协程挂起时要把自己的句柄交出去，恢复之后又要从表里摘掉。一开始我总忘摘，结果同一个协程被 `resume` 两次，行为各种诡异；后来理顺了"登记 → resume → 清除"的顺序，逻辑才算稳定。

再往后是非阻塞 socket。我给 `AsyncSocket` 写了四个 awaiter：`async_accept`、`async_connect`、`async_read_some`、`async_write_some`。每个 awaiter 的套路都一样：先立刻试一次，成功就直接返回；失败且是 EAGAIN，就挂起等事件循环；被唤醒后再试一次。于是服务端的核心逻辑长这样（示意）：

```cpp
while (true) {
    auto n = co_await client.async_read_some(buffer.data(), buffer.size());
    if (n <= 0) co_return;
    co_await write_all(client, std::string_view(buffer.data(), n));
}
```

按顺序读下来，就是挂起、唤醒、再挂起的循环，还挺有意思的。不过这部分也是参考了不少示例代码才写出来的，一开始还是挺迷茫。

中间也踩了不少坑。第一个是协程句柄的销毁没设置好，出现了悬垂指针，这还是写完扔给 AI 才帮我发现的。然后是跨平台：我最开始在 Mac 的 CLion 上构建，复制到 Win 本上之后满屏报错，那会儿也不太懂 POSIX 头文件怎么改，最后加了一层兼容层才跨平台成功。

最后至少能在两个终端里互相 echo 了，还不赖。虽然本质是个玩具，测试时也发现不少问题：首先是关停非常狼狈，`poll()` 的超时是 -1，会无限阻塞，就算在信号处理函数里调 `stop()`，服务端也不会自动关停，一时半会没想出来，后面也懒得改了，毕竟写着玩的成分更大。然后是一个 fd 只能挂一个读协程，这块就算想改也有点烧脑，想不出来，遂放弃。

总结来说还行，至少能跑就算赢。
